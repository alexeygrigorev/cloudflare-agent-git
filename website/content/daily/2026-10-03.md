# Day 1: 20 Ideas, No Agreed Six, and Where My Worktree Disk Went

On October 1, Cloudflare announced a [competition for the next Git platform](https://blog.cloudflare.com/next-git-platform-on-cloudflare/). I asked an orchestrator agent to create a [public repository](https://github.com/alexeygrigorev/cloudflare-agent-git) and gave the research to a team of coding agents.

I wanted wide exploration first, then zooming in on the most interesting ideas. My own Git problem went into the brief too: worktrees eat my disk.

This first daily report covers everything up to 04:24 Berlin time on October 3.

In this post, I'll share:

- How the agent team is organized
- Why the 20 ideas haven't become six yet
- What the agents measured on my worktrees, and where they disagreed with me
- Which claims they corrected
- What's still broken

## The team

I asked two lead sessions, Claude and Codex, to research Git and agent problems on Reddit, Hacker News and elsewhere. The experiment calls them principals. They had to pick 20 approaches, shortlist six and challenge each other.

Later I added more engines: Grok, Antigravity with Gemini, ZCode with z.ai models, and OpenCode with Space Bunny and Muse 1.3. An orchestrator agent on my desktop checks everyone every 30 minutes. My instructions are recorded verbatim in [USER-INSTRUCTIONS.md](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/experiment/USER-INSTRUCTIONS.md).

![How the team works](../../assets/team-workflow.svg)

I also told them to challenge me, and to invent better ways of working if mine didn't fit.

## 20 approaches, no agreed six

The principals collected [20 distinct approaches](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/approaches-20.md), from live conflict warnings to cheaper agent workspaces.

They didn't agree on six. In the [current shortlist draft](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/shortlist-6.md), Codex keeps five hypotheses and leaves the sixth slot open. Neither principal has signed it.

A01, Live Integration Radar, was the primary candidate. The agents wanted to warn agents about conflicts while they still work, not after they finish.

Then they tested two real coding agents writing at the same time under equal rules. Both arms produced compatible first commits and needed zero repairs. With no warnings issued, the run gave no evidence of benefit, so Claude proposed withdrawing A01 as primary. Codex accepted.

No candidate has passed the real gate yet: two actual coding agents working concurrently on Cloudflare Workers, with repositories in Artifacts, Cloudflare's Git-compatible storage.

## My worktree disk, measured

A git worktree is a second checkout of the same repository in another folder. An agent can work on its own branch there without touching mine.

I complained that worktrees copy the entire workspace. So the Claude principal ran a [read-only scan](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/claude/u7-real-worktree-measurement.md) of my server. It found 472 worktrees across 25 repositories, using 111.7 GiB of physical disk.

It first reported that dependencies and build output took about 80%. The orchestrator checked the arithmetic: the number mixed per-folder sums with a deduplicated total. Claude [corrected it](https://github.com/alexeygrigorev/cloudflare-agent-git/commit/e745294791e9087b00d9aafd0b7d76b63c47d6d3) to 69.4 GiB, or 62.1%.

Python virtual environments take 57.3 GiB of that across 215 folders, and they share nothing. Node packages take only 7.9 GiB because most are already hardlinked from a shared store.

So the agents partly disagreed with me: the pile is copied environments and old worktrees, not Git source. 264 worktrees point at commits already merged into main, though that alone doesn't make them safe to delete.

They also argued that a new Git platform may be an expensive fix for my problem. They proposed a cheaper "workspace doctor" that shares immutable environments between new worktrees.

Antigravity's first test on a pair of tiny tasks saved 53.15%, but read-only files had suppressed Python bytecode. After normalizing for that, the [saving dropped to 48.17%](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/antigravity/r8-uv-clean-state.md), below the 50% bar set in advance. Antigravity projects higher savings with three or more tasks. That projection hasn't been measured.

## Corrections on day one

The agents spent much of the first day fixing coordination:

- I couldn't see anything in the sessions, because the launch wrappers sent output to private files.
- Replies went to old sessions in the wrong workspace.
- One agent's commit swept up files owned by others.
- Some messages arrived twice.

The agents also corrected benchmark claims. A ZCode fixture reported a 67.8% saving, but it hardlinked writable source files, so tasks weren't isolated. An executor reported that formatting passed, but it had read the exit code of `tail`, not of the formatter. Space Bunny retracted a review handoff it had called complete.

The experiment log has a rule for this: an agent's report is a claim, not verification.

## Peers challenging each other

The engines review each other's priorities as well as the code. Codex [challenged the team](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/orchestrator/heartbeat-20261003T0024.md) for spending too much on tooling and asked to move real product tasks through their gates. Muse showed that deduplicating events by timestamp drops different events that share one.

The agents did complete one review chain on their own. Antigravity sent a ZCode revision to Muse for review, then sent the result to Grok, which updated its adoption decision. The orchestrator verified the whole chain without sending any scheduling input of its own.

But that was one bounded chain. At 04:24 the next Muse review hadn't appeared, and the inspected sessions had finished their turns. So I can't claim yet that the agents work continuously without supervision.

## A bug that isn't fixed, and a disk spike

The cold/default path in the tool that runs z.ai agents inside Codex executed the same shell command twice in a reproduced probe. An agent wrote a regression test for the repair, which expected exactly one execution and observed zero. The test [ended with 0 passed and 1 failed](https://github.com/alexeygrigorev/cloudflare-agent-git/blob/1c6c7dba5bc091e8e13677b8be788db857b17e4e/research/orchestrator/heartbeat-20261003T0224.md), so the bug isn't fixed.

Free disk also fell from 132 GiB to 116 GiB between two checks. The shared Rust build folder measures 39.65 GiB. The earlier 24 GiB figure was an agent's claim, not a measurement, so nobody knows yet what caused the 16 GiB drop. The orchestrator asked the owner to hold further compilation until the bytes are accounted for.

So the agents now face the same kind of disk problem I asked them to study.

## Next experiments

The agents need these results next:

- An accounting of the 16 GiB and a budget guard that actually stops builds
- A correctly bounded rerun of the failed regression test
- A fresh Muse review of the latest revision
- A workspace doctor run with Python and Node, where both trees pass tests and share no writable file
- Real tasks for the other lanes, such as a blind review test with a seeded bug

The [competition rules](https://www.cloudflare.com/documents/build-next-gen-git-platform-competition-terms.pdf) require entrants to be US or Canadian residents, so my eligibility is unresolved. If something valuable comes out, I'll look for a partner there.
