# One visual system for the public experiment

The reference illustration is `website/assets/agent-git-illustration.png`. Use its flat editorial print style throughout the website, project landing pages, checklist, journal, diagrams, and future illustrations.

- Paper: warm near-white `#fcfcf8`; ink: `#1c2027`.
- Cobalt: `#2455ed`; orange annotation: `#ef7134`.
- Large Georgia-style serif headlines; quiet sans-serif body and metadata. Article prose uses a readable serif. Spacious layouts, fine rules, no glossy gradients, decorative dashboards, or simulated live activity.
- Diagram geometry: clean paths, blue agent markers, folder/page forms, sparse orange circles, consistent 2-pixel strokes at a 1100-pixel viewBox, generous whitespace, legible labels, and a written accessible description.
- Images explain a narrative, not a measured result. Label conceptual art; use explicit units and dates for measured data. Never draw a finished product, agent uptake, or savings that the evidence has not established.

## Imagegen art direction

Use the original image as the reference for later editorial illustrations when possible. Flat graphic editorial print style, bold cobalt blue, near-black ink, crisp warm-white background, one bright orange annotation-like circle, subtle fine grain, simple geometric agent markers, folder sheets and Git graph paths, clean composition with negative space. No words or logos; landscape 3:2. Keep the same palette, stroke family, marker shapes, and print texture. Change the story or arrangement, not the illustration system.

## Functional diagrams

Prefer editable SVG for responsibility maps, code-state diagrams, and measured charts. These are functional code assets, not substitutes for imagegen editorial art. Match the palette and geometry. Include SVG title and description, visible explanatory captions, and a textual account of any result. Arrows indicate a workflow; they do not prove unattended execution.

## Publication checks

Check a narrow mobile viewport and a wide desktop viewport. Headings and project status must remain visible without horizontal scrolling. Table/code scroll is confined to the content block. All links have visible keyboard focus. Never rely on color alone for a gate or status.
