## Synthesis

### Unmet needs (nobody does well yet)
1. **Integration across many isolated agents.** Every vendor isolates (worktrees, containers, branches, per-agent repos) but stops at "open a PR" (E-C320 "does not merge changes back", E-C358). Nobody continuously integrates N agent heads, tells each agent early that its work now conflicts (textually or semantically) with a sibling, and proposes an order. Practitioner workarounds: file locks (E-C362, E-C328), shared contracts (E-C324), merge-agent (E-C365).
2. **Cross-agent awareness before conflict.** "How do agents know what others are working on" (E-C005) is solved only locally by GitButler's shared working dir + locks (E-C328) or ad hoc queues. No server-side, git-native "who is touching which file/symbol right now" signal.
3. **Cheap verification per agent.** Worktrees duplicate deps, ports, DBs, secrets (E-C319, E-C321, E-C322, E-C363); the top complaint is "manually verifying everything is working" (E-C321). Each agent having its own running preview URL is rare outside proprietary clouds.
4. **Review of N competing attempts.** Best-of-n exists (Cursor, Agent HQ) but comparison is manual; drift between attempts shows up only at the end (E-C323); review is the bottleneck (E-C326, E-C364).
5. **Provenance that survives integration.** Capture is crowded (Entire, Git AI, Agent Trace, SpecStory), but linking "why" to the *merge decision* (which attempt won, what was rejected, which conflict was resolved how) is not covered; Agent Trace explicitly leaves storage and rebase behaviour open (E-C335).
6. **Multi-repo agent work.** Worktrees break once agents cross repos; the remote becomes the only integration point (E-C361).

### Where Artifacts primitives give a unique edge
- **Repo-per-agent at ~zero marginal cost + fork** (E-C301, E-C309, E-C312): a server-side replacement for local worktrees, so isolation no longer costs local disk (E-C319) and matches the pkghost "remote is the only integration point" design (E-C361). Read-only forks give safe reviewer/judge copies.
- **Repo-scoped short-TTL tokens** (E-C305, E-C307): each agent gets write to only its own fork and read to base, a credential boundary local worktrees cannot give (all worktrees share one `.git`, E-C318).
- **Push events -> Queue -> Worker/Workflow** (E-C308, E-C311): a coordinator can react to every agent push in seconds, run a trial merge of all live heads, and notify siblings of new overlap. That is the "integration across agents" gap, built from documented primitives.
- **Workers Builds previews + CI SDK** (E-C310, E-C311): per-agent verifiable preview URL addresses the verification pain (E-C321) for Worker apps. Caveat: previews are per branch on one connected repo with `main`-only production, so the demo should use branches in a shared integration repo or the CI SDK Workflow path, not per-fork dashboard connections.
- **Native git notes** (E-C302): store attribution/decision records (Agent Trace-compatible) next to commits without rewriting history, i.e. adopt the existing spec instead of inventing one.

### Build-around constraints (from docs)
No documented merge/diff/commit-create/ref-update/branch-protection API in the binding (E-C305); no pre-receive hooks, events are post-hoc (E-C307, E-C308); push uses protocol v1 only; 1 GB/repo, 32 MB/blob (E-C306). So merges must be computed in a Worker (isomorphic-git or a Wasm merge driver such as weave, unverified) or in a Sandbox, then pushed back. Billing start date conflicts: Oct 14 (docs) vs Oct 15 (competition post) (E-C311).

### Crowded areas to avoid as the main pitch
- Local worktree/agent orchestrator UIs (Conductor, Vibe Kanban 28k stars, Claude Squad, Crystal, Sculptor, container-use; E-C353..E-C357), plus vendor-native worktrees in Claude Code/Codex/Cursor.
- Session/attribution capture alone (Entire, Git AI, Agent Trace, SpecStory; E-C335..E-C338). Cloudflare already dogfoods session-repo + fork (E-C303).
- Generic merge queues and stacked PRs (GitHub, Graphite+Cursor, Mergify, Trunk, Aviator; E-C341..E-C343, E-C348).
- "@agent resolve the conflict" as a single feature (GitHub ships it, E-C344).
- "Git hosting API for agents" as infra (Pierre, Cursor Origin, Artifacts itself; E-C349, E-C351). HN skepticism on why not GitHub+worktrees (E-C315, E-C352) means the demo must show something GitHub cannot: live cross-agent integration with per-agent previews, not just storage.
