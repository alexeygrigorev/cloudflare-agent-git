## Configured duties and grace

Coordinator is an enrolled role, independent of desktop location or provider. Any eligible Hetzner agent can ACK candidacy and win; stable priority then authentic identity breaks ties. A project/subproject has explicit slots and candidates; no inheritance of someone else's credentials. Principal promotion atomically invalidates the promoted head authority and creates head backfill work while preserving children. Replacement agent enrollment uses maintained gated launcher, actual model startup, new genuine identity, role startup docs, custody ACK and first useful action, without a human/root approval queue.

Default: deterministic watcher every 60 seconds; lease TTL 180 seconds with renewals every 60 or less; semantic sync timeout 120 seconds; first useful takeover action deadline 300 seconds. Coordinator periodic checks every 30 minutes and standup daily 09:00 Europe/Berlin, keyed by schedule revision/local date to dedup DST-aware scheduling. Due time is not itself a failure: allow explicit scheduled-run grace of 120 seconds, issue one exact sync/diagnostic incident, then elect only using the serialized authoritative expiration/revocation decision. Implementation defaults must match this adopted config or document/accept a measured revision before runtime rollout. Lease/process contact cannot renew missed check outcomes forever. Longer genuine productive model work can have an acknowledged expected checkpoint; preserve useful children even when coordination custody fails.

Each missed checkpoint result includes metric target/actual/coverage, confirmed cause vs hypothesis, owner, action already executed, outcome, next step/dependency/deadline and independent verification. A timer PID, local sync event, raw launch count or queued handoff is insufficient. Desktop periodic automation remains paused in this chat; new remote coordinator schedules must be registered by actual custody owners, not duplicate scheduler creation.
