## 3. Mechanism Explanation: Why `systemd-run --scope` Dropped Environment Variables by Default

### 3.1 Transient Scope Unit Creation
When launching commands inside a transient cgroup scope via `systemd-run --user --scope`, systemd creates a transient scope unit via DBus (`org.freedesktop.systemd1.Manager.StartTransientUnit`).

### 3.2 Environment Stripping Behavior
By default, `systemd-run` handles environment setup for transient units through the user manager's default execution context:
1. Ambient environment variables from the invoking Python or shell process are **not** unconditionally propagated into the scope unless explicitly declared.
2. Even when `subprocess.Popen` is invoked with `env=clean_env`, the `systemd-run` binary negotiates unit parameters with `systemd --user`. Without explicit command-line environment bindings, `systemd-run` launches the unit payload with the systemd user manager default environment table, where `TMPDIR`, `TEMP`, and `TMP` are unset.
3. When nested child processes (such as Python scripts, model adapters, git CLI commands, or compiler probes) start, standard libraries inspect environment variables in standard precedence:
   ```python
   # Python standard library tempfile.py logic:
   for env in ("TMPDIR", "TEMP", "TMP"):
       if env in os.environ:
           return os.environ[env]
   return "/tmp"  # Fallback to host root /tmp
   ```
4. As a result, when `TMPDIR` was stripped by `systemd-run`, child processes silently defaulted to `/tmp`, polluting the underfloor filesystem and breaching isolation boundaries.

## 4. The Architectural Solution: Dual-Layer Containment (C2134 / C2136)

To provide fail-closed containment against environment stripping, a dual-layer defense was implemented in `execute_in_verified_systemd_scope`:

### 4.1 Layer 1: Outer Systemd CLI Flag Binding (`-E`)
`launcher_bus_bridge.py` explicitly attaches `-E` arguments for `TMPDIR`, `TEMP`, and `TMP` directly to the `systemd-run` invocation:

```python
# launcher_bus_bridge.py lines 1502-1516
scope_cmd = [
    "systemd-run",
    "--user",
    "--scope",
    "--collect",
    f"--unit={unit_name}",
    "-p", f"MemoryMax={requested_memory_mb}M",
    "-E", f"TMPDIR={tmpdir_path}",
    "-E", f"TEMP={tmpdir_path}",
    "-E", f"TMP={tmpdir_path}",
    "--",
    sys.executable,
    str(prelude_script),
] + list(command_argv)
```

This instructs the systemd scope manager to inject and retain `TMPDIR`, `TEMP`, and `TMP` directly in the execution context of the scope unit.

### 4.2 Layer 2: Inner Prelude In-Process Environment Restoration
Before transferring execution to the actual child payload, the Python prelude script (`prelude_script`) explicitly restores and enforces `TMPDIR`, `TEMP`, and `TMP` in `os.environ` immediately before calling `os.execvp`:

```python
# launcher_bus_bridge.py lines 1492-1497 (inside prelude_code)
# Enforce contained scratch TMPDIR before execvp into child payload (C2134)
os.environ["TMPDIR"] = "{tmpdir_path}"
os.environ["TEMP"] = "{tmpdir_path}"
os.environ["TMP"] = "{tmpdir_path}"

os.execvp(sys.argv[1], sys.argv[1:])
```

Because `os.execvp` replaces the process image in place without spawning a new shell or resetting environment tables, the child process payload inherits the exact, sanitized environment table with `TMPDIR` pointing to the owned scratch directory.
