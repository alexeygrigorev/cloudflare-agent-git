## 1. Context & Problem Statement

In incident C3088/C3090, 28 consecutive delivery attempts of request `01a113c8-c588-7690-9144-1b377495e733` to `codex-principal` were rejected over 11,000 seconds with `status: not-ready`:
`"recipient composer has an unsubmitted draft in progress (GPT-6.1-Sol medium · Context 58% left · ~/git/cloudflare-agent-git · Context 42% used · we…); delivery fail-closed"`.

Root-cause analysis revealed two compounding defects:
1. **Awareness Banner Misclassification**:
   In `scripts/supervision/service.py`, `COMPOSER_TAIL_CHROME_RE` only matched a single line containing `Aplexer awareness bootstrap.*`. However, the standard Aplexer awareness bootstrap output spans 10–15 lines (`Before editing files, run a context...`, `Declare your work before touching files...`, `git: worktree...`, `peers (10):...`, `shared paths (advisory):...`). Any occurrence of these banner lines following an empty prompt caused `composer()` to fail into `'unknown'`.
2. **Delivery Retry Hammering**:
   When `aplexer message deliver` returned `not-ready` on footer classifier mismatch, `service.py` marked `diagnostic_hold = 'known-footer-classifier-mismatch'` but lacked a dedicated backoff. Consequently, every supervisor cycle immediately re-attempted delivery, resulting in 28 failed attempts without allowing time for state reconciliation.
3. **Missing Process / Role Vacancy Handling**:
   When monitored leaders died or became permanently unresponsive (>2x retry SLO), `service.py` only appended dead escalation notices without triggering the reviewed role failover election protocol (Candidate 43ea / commit `43ea3400965e690206f823640173992a9ea0c7b4`).

## 2. Technical Modifications

### A. `scripts/supervision/service.py`
1. **Multi-Line Awareness Banner Tolerance**:
   Expanded `COMPOSER_TAIL_CHROME_RE` to match all multi-line strings generated by the Aplexer awareness bootstrap banner:
   ```python
   COMPOSER_TAIL_CHROME_RE = re.compile(
       r'^\s*[─━_=-]+\s*$'
       r'|.*(?:Context|for shortcuts|auto mode|manage|monitor|agents|tokens|GPT-|Gemini|glm-|usage|workspace|warning|Worked for|Ask Codex)'
       r'|.*(?:Aplexer awareness|Before editing files|Declare your work|Check peer mail|participate in \d+ workspace|Workspace coordination|git:\s*worktree|you:\s*\S+|peers\s*\(\d+\)|shared paths|peer-provided data).*'
   )
   ```
2. **Delivery Retry Cooldown**:
   When `status == 'not-ready'` and `diagnostic_hold == 'known-footer-classifier-mismatch'` (or when detail matches awareness banner strings), sets `item['cooldown_until'] = time.time() + 180`. This enforces a 3-minute backoff before the next attempt, eliminating the rapid-fire retry loop while preserving the pending envelope.
3. **Candidate 43ea Failover Trigger**:
   When a monitored leader is un-alive (`alive == False` / missing process) or `blocked_beyond_slo` with a pending message for > 2x `retry_slo_seconds` (600s):
   - Sets `item['failover_candidate'] = True` (suppressing delivery attempts to dead processes).
   - Emits structured `failover-candidate-action` event with `candidate: '43ea'`, `candidate_pin: '43ea3400965e690206f823640173992a9ea0c7b4'`, role vacancy flag, and trigger condition.
   - Symmetrically implemented across both principal and head monitoring pipelines.
