**Why read this:** choose the next operation when work completes, fails or waits on a dependency. Read at startup, on changes and when flow stalls. Role authority is in ROLE-CONTRACT; resource admission is in RESOURCE-POLICY; current owners/dues are in the tracker.

## Head-owned loop

1. Capture each human requirement as a task or explicit constraint/supersession; preserve source and history.
2. Build an executable task packet: owner ACK, scope, dependencies, acceptance/falsifier, workspace, checkpoint and continuation/recovery trigger.
3. Dispatch real scoped model work through the maintained launcher. Register executor/host/team/parent/generation and actual first action. Follow [HEAD-TASK-LOOP](continuation-runtime/HEAD-TASK-LOOP.md); no raw-provider shortcut or built-in Claude Agent/Task substitute.
4. Checkpoint the result; obtain distinct pinned review. Repair rejected work through an implementer until accepted. Acceptance, integration, release and human delivery remain separate.
5. Persist the successor obligation and start the next useful ready task. A failed refill opens owned recovery; it does not vanish behind a successful predecessor exit.

Heads delegate independently owned work in parallel where useful; no fixed team cap and no make-work. Principals monitor all teams, challenge evidence, resolve cross-team dependencies and follow repairs through resumed action. Remote event handling/lightweight due scans run between model turns; desktop checks are not the task clock.

## Failure and timing

Every miss names the task, confirmed cause versus hypothesis, diagnosis/repair/workaround already executed, actual result, verifier, next owner/action/due and durable trigger. If a remedy produced no action, change it or obtain a received healthy-owner handoff. Protect productive sessions and reconcile uncertain effects before retry.

Use task-specific adopted checkpoints. Legacy5-minute idle/completion and20-minute initial-progress objectives, and the newer5/10/15 pilot, are operating targets, not installed guarantees. Exceptions are agreed in advance and preserve original misses. Busy computation can be real progress without commits; use task-appropriate evidence. Independent useful work continues while another task waits.

## Storage, adoption and measurement

TASKS.json is currently canonical; use its guarded CAS/history writer and `.local/task-registry.lock`, preserving every other row. TEAM-REGISTRY records actual received custody. DELIVERY-BACKLOG is an intake audit, not proof of fulfillment. A tracker migration needs explicit authority cutover, preserved IDs/history and in-flight reconciliation.

Keep ordinary Git fallback and lightweight independent source checkpoints, with a disposable restore test. Adopt Agent Branches in real isolated development only where verified. Preserve dirty peer code; do not copy dependencies/caches/workspaces for backups or delete existing worktrees.

Existing metrics/supervision services retain private UTC time series, bounded retention and source coverage. Distinguish useful workers from live heads/services, observed usage from cumulative conversation totals, and accepted outcomes from activity. Unknown stays unknown. No public raw metrics/transcripts or unauthenticated metrics port.
