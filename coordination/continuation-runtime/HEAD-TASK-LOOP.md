## Per-task contract and evidence states

1. **Intake/scoping:** Preserve human source and taskID; define acceptance criteria, non-goals, actual internal user, source repo/full SHA/tree, workspace, exact edit scope, integration owner, lease epoch, dependencies, generous bounded timeout, tiny scratch estimate and recovery path. Unknown/missing owner ACK is not ready.
2. **Ready/queued/admitted:** Head ACKs the owned contract. Fresh quota, account/individual limits, actual occupancy, host and aggregate scratch checks plus genuine reservation/source validation permit launch; queued/starting/PID labels alone are not running.
3. **Running:** Capture actual external provider/native actor, head/parent/team, mode/model/version, taskID, launcher invocation/unit and FIRST completed useful model tool. Keep private logs and incremental outputs; do not publish auth or full raw transcripts.
4. **Completed-awaiting-review:** Require actual provider terminal result and artifact hashes; preserve explicit unit exit unknown if collected. A head-authored postmortem after timeout, model narrative, or default collected-unit status cannot replace worker completion. Failed/cancelled work keeps its actual history; useful partial artifacts remain separate.
5. **Independent review:** Launch a distinct external reviewer on the exact final full source SHA/tree and code/artifact hashes. Reviewer has read-only scope, reproduces relevant positive/negative acceptance paths and returns a free verdict with bound actual actor/first-tool/terminal/report digest. Stale, self-authored, reused or required-agreement reviews fail closed. Automated tests are validation, not an independent model reviewer.
6. **Repair loop:** On CHANGES_REQUESTED, send every finding verbatim to an external implementer; head does not patch code itself. Re-pin final bytes and request distinct review again until APPROVED. Provider/quota failure or timeout is no code verdict: diagnose, preserve work and choose a gated supported alternative. BLOCKED means unproved, not permission to integrate.
7. **Integration/resolution:** Existing integration owner verifies reviewed exact bytes, recovery/remote checkpoint and deployed or real-user behavior required by the task. If bytes change after approval, re-review. Source-only acceptance cannot close a loaded runtime/physical device task. Record accepted evidence and unique resolvedID/event time; do not backfill unknown historic times as now.
8. **Next useful task:** Head immediately selects a disjoint genuinely ready contract and repeats through the maintained launcher. Review/integration/dependency/failure events drive the loop; durable continuation and independent recovery back it up. A final turn is a checkpoint, not project completion.

## Isolation, recovery and continuation

Keep issue-scoped implementer/reviewer workspaces and explicit non-overlapping paths. Sequential handoff on overlapping paths requires genuine custody; a stopped parent or old registry label is not a new edit-scope claim.
