## Daily-report checklist coverage

The canonical executable writer checklist is [DAILY-REPORT-CHECKLIST](DAILY-REPORT-CHECKLIST.md), owned by the governance publisher. The coverage checklist below is a consolidated requirement cross-check, **not a second writing contract or a verbatim human quotation**. - [ ] State report date, exact preceding24h window, timezone and data_as_of; use hourly per-project breakdown.
- [ ] Cover Agent Branches, Agent Dashboard, Agent Quota Launcher and Cross-computer Agent Coordination separately.
- [ ] Explain concrete useful changes/accepted features and their user benefit; distinguish source tests, local fixtures, loaded runtime and real adoption.
- [ ] Include aligned active-agent, commit and unique accepted resolved-task statistics; created/open/closed counts and a short overview of closed tasks in each project.
- [ ] Show truthful current ACTIVE/50 and executable ready reserve, provider breakdown, first-action/outcome evidence, measurement coverage and unknowns; separate heads/principals/services/controllers/queued/completed.
- [ ] Report tokens/usage/cost only from actual measurements; keep missing data unknown and never translate quota percentages into token usage or money.
- [ ] Include Continuation Runtime **process and runtime** every day: enforced task flow, delivered versus planned, current wake/refill/failover/restart acceptance and latest decisions/agent suggestions.
- [ ] Include failures, missed checkpoints and unfinished dependencies with named current owner, diagnosis versus hypothesis, actions already taken, evidence/independent verdict, resumed work and next action/checkpoint/trigger.
- [ ] State launcher selection/admission rules, verified campaign/expiry conditions and quota/resource limits; avoid claiming unverified provider headroom.
- [ ] Explain real Branches dogfooding and independently recoverable GitHub/main checkpoints; distinguish source synchronization from accepted integration.
- [ ] State cross-computer/headless Bus adoption and offline/nonSSH boundaries honestly; do not substitute oldSSH/localloopback for the actual gate.
- [ ] Cover requested cloud execution versus lightweight coordination/storage budget calculations and current unknown usage/overage bounds when relevant; no unfounded hard-cap claim.
- [ ] Use the dedicated genuine Claude Opus writing lane, stylint and documented Substack voice; plain reader-facing language without internal IDs/hash jargon in prose.
- [ ] Include useful diagrams and ImageGen illustrations in the approved shared editorial style; apply visual/functional/editorial independent quality gates.
- [ ] Retain approved good assets/editions, preserve privacy, show meaningful public outcome cards and put statistics inside the report rather than using numbers as its title.
- [ ] Verify public publication/report-feed delivery and recovery through the publication coordinator; no duplicate writer, edition, scheduler or social posting.
- [ ] Explicitly record checklist evidence and unresolved items in the preparation/review handoff; never silently tick an unmet requirement.
