# Enforcement: gates and proof

**Why read this:** decide what acceptance evidence a claimed control still owes. Consult the affected row each check and before declaring deployment/autonomy. Required controls are not a claim of comprehensive installed enforcement. Current implementation owners/ACKs/dues are in the tracker; archived actor IDs and incident snapshots are not routing instructions.

| Boundary | Must enforce | Acceptance gap / existing route |
|---|---|---|
| Intake/task writers/checkouts | Stable IDs/history, CAS, scope/epoch and valid transitions | Guard helper exists; all writers/checkout and semantic authorization need proof. Principal coordinates tracker/reconciliation owner. |
| Assignment/Bus | Persist notification obligation; genuine recipient, scope, stable intent and dedup | Durable messages exist; atomic state/outbox and task-action authorization remain to prove. Existing Bus/supervisor. |
| Launcher | One loaded config/store/controller, fresh quota/reservations, current ownership and first action | Ordinary callers/fencing and conflicting stores need acceptance. Existing QL source lease. |
| Review/acceptance | Exact artifact and task criteria, distinct executed review at every entry point | Normal CLI/API bypass must be negatively tested. Existing head and distinct reviewer. |
| Terminal/refill | Task/invocation/owner/generation binding; durable successor or recovery obligation | Optional bindings and refill errors cannot silently pass. Existing QL/supervisor owners. |
| Due/failover | ACK/action/review/delivery dues, bounded recovery, protected readiness and target-side fencing | Source fixes and callbacks do not prove safe recipient wake or absent-root cycles. Current received Ant/supervisor custody. |
| Source/runtime | Reviewed artifact plus actual loaded module/binary/config/store | Manifest/reload work exists; source equality/restart alone insufficient. Existing runtime owner. |
| Physical cross-host work | Reviewed HTTPS/enrollment, device-local secrets, scoped action, reconnect/cursor reconciliation | Host-local transport/source sync insufficient. Existing Bus/Win35 owners. |
| Integration/publication/delivery | Received source lease, reviewed exact revision/assets, actual release and shown result | No implicit main or approval from readiness. Existing integration/publication owner; root delivers. |

## Required acceptance

For each row bind candidate hash, installed paths/version, actual loaded configuration/store, actor/host/generation/epoch, executed outcome and independent receipt. Enumerate production callers and bypasses. Controls in a helper do not protect callers that bypass it. Unrestricted same-OS-user shell/file access remains an explicit boundary; no universal prevention or global ACL changes are claimed.

Test legitimate work plus:

1. Crash after assignment before send; duplicate delivery and changed payload; recover one logical obligation.
2. Missing ACK, ACK without action, stalled progress and failed refill; recovery produces actual useful first action.
3. Stale epoch/PID reuse, fabricated role/parent/team, unreceived scope; reject at real dispatch/write/integration targets.
4. Busy/draft/menu/unknown/quota-error readiness; preserve work and continue eligible independent tasks.
5. Self-review, missing witness, artifact changed after review and direct acceptance bypass; reject consistently.
6. Lost receipt after external effect; reconcile before retry. Concurrent writers/checkout preserve every ID/history.
7. Root/principal absent: two useful completion→distinct review→acceptance→successor first-action cycles plus worker/reviewer/recovery failure. Timers/toy consumers do not count.
8. Physical Win35 partition/reconnect and tracker outage/staleness: scoped recovery, no duplicate effect/stale integration, fresh canonical parity and read-only fallback.
9. Human delivery: actual result; published report URL, brief summary and accepted fresh illustration evidence.

Track transition/recovery latency, due/orphaned obligations, failed refill and human reminders/manual rescues alongside accepted outcomes and coverage. Fewer alerts without evidence is not success. A failed gate creates a persistent task with an executed mitigation, current owner, next due and durable trigger.
