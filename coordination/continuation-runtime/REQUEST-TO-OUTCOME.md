# Request → accepted, delivered outcome

**Why read this:** find the exact transition that failed and what action is owed. Consult every check, then the affected task contract. A captured request, message delivery and technical completion are different events.

| Transition | Proof required | If missing |
|---|---|---|
| Request → captured | Stable ID, exact source/time, acceptance and constraint/supersession mapping | Reconcile intake without losing existing rows/history |
| Captured → owned/ready | Genuine current owner ACK, scope, dependencies, next action/due and recovery trigger | Resolve custody or received handoff; assignment is not ACK |
| Ready → executing | Fresh admission and task-bound first model tool or deterministic operation receipt | Diagnose dispatch/store/recipient; do not count launch/PID as useful work |
| Executing → review | Pinned artifact, terminal receipt and relevant executed tests | Preserve failures and route actual repair |
| Review → accepted | Distinct genuine reviewer, exact digest and semantic criteria | Repair or obtain missing independent review; no self-review/bypass |
| Accepted → delivered | Required integration/release verification and actual human-visible result | Keep delivery obligation open; draft/source link is not published URL |
| Accepted → next action | Durable successor obligation, executable work and actual first action | Persist owned refill recovery; predecessor remains separately accepted |

Every transition binds task/attempt, actor/host/parent/generation/epoch, occurrence time, predecessor and evidence digest. Preserve failed attempts, original misses and reopen/supersession reasons. Parent requests close only when all criteria and delivery are met or the human cancels/supersedes them.

## Recovery and timing

Use adopted task-specific timestamps. The5-minute ACK/10-minute first-action/15-minute progress operating pilot is not an installed timer or universal promise. Agree longer computation checkpoints in advance. Event/dependency/failure handling and due scans belong to the existing supervisor; proposed<=60-second scanning needs loaded proof. Desktop30-minute checks audit and recover failed custody, not dispatch every task.

On a miss execute bounded diagnosis, repair/workaround or received handoff. Record actual result, resumed action/independent verification, next owner/action/due and trigger. If a remedy fails to act, change it. Two missed semantic checkpoints can invoke the existing reviewed failover path only after genuine readiness/loss, exclusive fenced epoch and successor ACK; timeout is not authority.

State plus notification obligation must be durable and reconciled across crashes. Separate file writes do not prove transactional outbox behavior. Use stable intent IDs, reject changed payloads and reconcile uncertain external effects before supported retry. Protect pending envelopes, histories and drafts; never force unknown/busy readiness.
